# Throwbox v1.1.0

**Let an AI agent work on your code without giving it your computer.**

The last planned release. Throwbox (formerly Cloud harness) is an open-source project showing how to run an AI coding agent safely. It is a prototype you run yourself, not a product.

## New

- **A capped key per run (optional).** With `OPENROUTER_MANAGEMENT_KEY` set, each run gets its own OpenRouter key, capped at $0.10 by default, expiring after 30 minutes and deleted when the run ends.
- **Test command.** The runner detects PHP, Node or Python tests; you can type a command or `skip`.
- **One-click draft PR** into repos you list in `PR_REPOS`.
- **Zero data retention** note in the README.
- **A new name,** and a README that opens with what building it taught us.

## What we found

A deleted OpenRouter key was still accepted 15 s after deletion and refused at 20 s (one measurement, of the key-info endpoint). The spending cap and expiry are the safety net, not deletion.

## Upgrading

Rebuild the MicroVM image: the runner changed since v1.0.0. All new `.env` settings are optional.

## What was checked

Real runs on one account, a few of each; see [VALIDATION.md](https://github.com/johnsiega/throwbox/blob/v1.1.0/docs/VALIDATION.md) sections 11 to 14. `npm test`: 624 tests, 618 pass, 6 skipped (real-AWS tests).

## Not checked

- Model calls with a deleted key, and how the cap treats a request already in flight.
- The 180 s install limit, `npm ci` falling back to `npm install`, Node packages downloaded from the network.
- Draft PR error paths against real GitHub.
- More than 4 runs at once (this account's quota).
- The AWS setup steps on a clean account.
- `scripts/check-run-keys.ts` expects a deleted key to be refused at once, so it exits 1.

## Not done

The one-command AWS setup script was planned and **dropped**; its spec and plan stay in the repo if you want to build it. Also not done: restricting the sandbox's internet access, private repos, forks, hosting and sign-in.
