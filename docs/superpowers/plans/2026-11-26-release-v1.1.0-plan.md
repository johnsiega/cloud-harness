# Release v1.1.0: plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking. This plan writes no product code.

**Goal:** Tag and publish v1.1.0 once items 1 to 3 have shipped. The docs and numbers must match what was measured, and the release notes must say plainly what is and is not proven.

**Architecture:** Docs and git only. The same procedure as v1.0.0 (tag `v1.0.0` at `d1c38fc`; `gh release create`).

**Spec:** none needed. Scope comes from the v1.1.0 brief (2026-11-26): items 1 to 4, and the out-of-scope list.
**Status:** ready for the owner's review. It runs after the plans for items 1, 2 and 3 are complete, or once the owner decides to ship without one of them (the notes then say so).

## Global Constraints

- **Tagging and publishing are each a public [go].** No tag is pushed and no release is created without them.
- Every push is public. Scan the whole diff since `v1.0.0` (`git diff v1.0.0..HEAD`) for `sk-or-`, `github_pat_`, `AKIA`, 12-digit account ids, the owner's email and `C:\Users` paths. Never commit `.env` or `media/`.
- CI must be green on the exact commit that gets tagged (`gh run list --commit <sha>`).
- Every number in the README or the release notes must point to a section in VALIDATION.md with its sample size and date.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
